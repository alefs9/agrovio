# Organización para tres personas

Asignación sugerida, a completar con nombres. Trabajar por ramas y PR; no hacer que los tres modifiquen a la vez el mismo archivo.

| Responsable | Área principal | Primera tarea |
| --- | --- | --- |
| Persona 1: ____ | Landing y UI React: apps/landing, packages/portal | FE-02: preparar el adaptador API y validar pantallas con el cliente |
| Persona 2: ____ | Backend Python, modelos y permisos | BE-01: definir identidad y persistencia; implementar publicaciones |
| Persona 3: ____ | Integraciones, demo y verificación | INT-01: revisar número/servicio WhatsApp; QA-01: automatizar navegador |

`packages/domain` y el contrato de API se cambian con revisión de al menos otra persona. Cambios compartidos pequeños; no reescribir el portal entero desde una rama de una función.

Proceso: elegir tarjeta → asignar responsable → rama `feat/FE-01-publicaciones` → implementar y probar → PR con capturas/recorrido → otra persona revisa → integrar. Usar un contrato acordado para trabajar en paralelo, sin asumir que una pantalla implica una regla aprobada.

Cada tarjeta debe tener responsable, alcance, entradas/salidas, dependencias y comprobación. No incluye estimación de precio ni nuevas condiciones contractuales.
